## 4. 実装範囲（やること）

以下5本のテストを実装する。UI操作は既存の`e2e/`配下の対応するテストの操作手順を参考にし、
アサーションは`window.__dexieDb`経由の直接確認（Firebase Admin SDKでの確認に相当）を併用する。

1. **`master-data-persistence.spec.ts`**: 集合場所または家庭をUIから追加・保存し、
   ページをリロードした後も表示され続けることを確認する（IndexedDBへの永続化確認）
2. **`event-response-carpool-flow.spec.ts`**: `seedDexie`で集合場所・目的地・家庭・選手を
   投入し、イベントを作成、回答入力画面で参加回答を入力、「配車作成」ボタンで自動配車を実行し、
   配車結果画面に選手が正しく配置されることを確認する（DexieRepositoryの読み書きチェーン全体）
3. **`carpool-drag-and-drop.spec.ts`**: 配車結果画面で人カードを別の車へドラッグ&ドロップし、
   移動元・移動先の両方の車の乗車メンバーが正しく更新されることを確認する
   （`saveCarpools`の原子性・upsert確認）。ページリロード後も結果が維持されることも確認する
4. **`family-delete-cascade.spec.ts`**: `seedDexie`で選手・コーチ・家族を持つ家庭を投入し、
   家庭編集画面から家庭を削除する。`window.__dexieDb`経由で、選手・コーチ・家族の
   レコードも道連れで削除されていることを確認する
5. **`past-events-pagination.spec.ts`**: `seedDexie`で`PAST_EVENTS_PAGE_SIZE`
   （`src/repositories/CarpoolRepository.ts`からimport）を超える件数の過去イベントを投入し、
   ホーム画面の「過去のイベント」を「もっと見る」で複数ページたどり、
   全件が重複・漏れなく表示されることを確認する

各テストファイルの冒頭に、対応する既存e2e（自チーム版）のファイル名を`ref:`コメントとして
記載し、UI操作手順の参照元を明示する。

## 6. 受け入れ条件

- `npm run test:e2e:public`で5本すべてがグリーンになる
  （このセッションのサンドボックス環境ではPlaywrightブラウザバイナリのバージョン不一致で
  実行できない可能性がある。その場合はコードレビューベースで正確性を確認し、
  実行結果はCI環境で確認する）
- 各テストが他のテストの実行順序に依存しない（Playwrightの既定のテスト分離を前提にする）
