## 2. このタスクのゴール

データのバックアップ機能（書き出し・読み込み）について、自チーム版（`e2e/`、Firebase
Emulator前提）・公開版（`e2e-public/`、IndexedDB前提）それぞれにスモークテストを追加する。

## 3. 変更対象ファイル（想定）

- `e2e-public/backup-export-import.spec.ts`（新規）

---

## 4. 実装範囲（やること）

両ファイルとも、既存のマスタ投入ヘルパー（自チーム版はFirebase Emulatorへのseed、
公開版は`e2e-public/utils`のIndexedDB投入ヘルパー）でテストデータを用意したうえで、
以下を検証する。

1. 登録情報ハブ画面から「データのバックアップ」へ遷移できる
2. 「バックアップを書き出す」でファイルダウンロードが発生する
   （Playwrightの`page.waitForEvent('download')`でファイル名・内容を検証する）
3. ダウンロードされたJSONを`data.schemaVersion`だけ書き換えたファイルを用意し、
   「ファイルを選択」でそれを読み込ませると、確認ダイアログを経由せずエラー表示になる
   （データが変更されていないことを、既存データの件数表示等で確認する）
4. 書き出したファイルをそのまま「ファイルを選択」で読み込み、確認ダイアログで
   「読み込む」を選択すると、ホーム画面へ遷移し完了トーストが表示される
5. 上記4の後、登録情報画面（家庭・集合場所等）を開き、元のデータと同じ件数・内容が
   復元されていることを確認する

## 5. 実装範囲外（やらないこと）

- 自チーム版での「読み込む」実行者を絞る仕様のテスト（そのような制限を設けない方針の
  ため対象外。docs/12_データバックアップ機能設計.md#9）
- 開発用「サンプルデータ投入」機能との統合後の回帰テスト（統合タスクが別途発生した
  時点で追加する）

### 既知の制約

`e2e/backup-export-import.spec.ts`はFirestore Emulatorの対象コレクションを丸ごと
削除する（インポートによる全置換）ため、他のspecファイルと同時実行されると
巻き込んで失敗させる可能性がある。`playwright.config.ts`はCI実行時のみ
`workers: 1`（逐次実行）に固定しているためCIでは問題にならないが、ローカルで
`npm run test:e2e`をworkers未指定（並列）で実行する場合は稀に無関係なテストが
落ちることがありうる（spec内のコメント参照。`--workers=1`で回避可能）。
