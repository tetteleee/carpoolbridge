# 1. 目的・位置づけ

本ドキュメントは、`docs/08_公開版アーキテクチャ設計.md`・`docs/10_DexieRepository実装設計.md`・
`docs/11_PWA化設計.md`・`docs/12_公開版配布・ホスティング設計.md`のすべてで
「別資料・別フェーズで扱う」として対象外としてきた、公開版（`carpoolbridge-go.web.app`）の
**TWA化・Google Playストア公開**を初めて対象とする設計書である。

対象はあくまで公開版（Dexie/IndexedDB版）。自チーム版（Firestore版・要認証）は
Google Playでの配布対象ではない。

以下は人間による決定事項（本ドキュメント作成前に確認済み）。

- TWAラッパー（Android Studioプロジェクト・Bubblewrap生成物）: **本リポジトリに含める**
- プライバシーポリシーページ: **公開版アプリ内に静的ページとして追加する**
- 本ドキュメント作成後、このスレッドで着手する実装範囲: **リポジトリ内で完結する準備作業まで**
  （`.well-known/assetlinks.json`を配信できるようにするための`firebase.json`修正、
  プライバシーポリシー静的ページの追加）。TWAラッパー本体の生成（Bubblewrap実行・
  Android Studioプロジェクト作成）は、Android SDK等のツールチェーンを要し、
  この実行環境（クラウドの作業セッション）には無いため対象外（4.2節参照）。

# 2. TWAとは何か（前提知識）

**TWA（Trusted Web Activity）**は、PWAをAndroidアプリの形でGoogle Playに公開する
標準的な方法。Androidアプリの皮を被せ、中身は実際の公開版PWA
（`carpoolbridge-go.web.app`）をChromeエンジンで表示する仕組み。新しく別のアプリを
作るわけではなく、公開版PWAをそのままラップするため、Web側の実装（本リポジトリの
`src/`・公開版ビルド）に変更は不要。

生成にはGoogle公式CLIの`Bubblewrap`、またはMicrosoft製Webツール`PWABuilder`を使うのが
一般的。

# 4. 決定事項の詳細

## 4.1 TWAラッパーの配置場所: 本リポジトリに含める

**提案**: 別リポジトリに分離せず、本リポジトリ（`carpoolbridge`）内に含める。

**メリット**: Web側（公開版PWA）の変更とTWA設定（`assetlinks.json`・Bubblewrapの
`twa-manifest.json`等）の対応関係を同一リポジトリ内で追える。バージョン管理・
デプロイタイミングの一元管理ができる。

**デメリット**: リポジトリの責務が「Webアプリ」から「Webアプリ＋Androidラッパー」に
広がる。Android関連ファイル（Gradleプロジェクト等、生成後）が加わりリポジトリ規模が
増える。

配置先ディレクトリは、TWAラッパー生成に着手する時点（4.2節が対象外でなくなった
タイミング）で改めて決める（例: `android/`）。現時点ではディレクトリを新設しない。

## 4.2 TWAラッパー本体の生成: 本スレッドでは対象外

Bubblewrapによるプロジェクト生成には、JDK・Android SDKのセットアップ（数百MB〜数GB
規模のダウンロード）と、生成後のビルド確認が必要になる。本スレッドが動作する
クラウドの作業セッションにはAndroid開発ツールチェーンが無く、これらを対話的に
確認しながら進める前提のセットアップには適さない。

**変更案**: TWAラッパー生成は、Android SDKを利用できるローカル環境、または
専用に用意したセッションで、人間が立ち会いながら次フェーズとして進める。

本ドキュメントでは、その前段としてリポジトリ側で今すぐ・低リスクに対応できる
準備（5章・6章）のみを今回のスコープとする。

## 4.3 プライバシーポリシーページ: 公開版アプリ内に静的ページとして追加

**提案**: 別サイト（会社サイト・外部ドキュメントサービス等）を用意せず、公開版PWA内に
`/privacy`ルートの静的ページを追加する。

**メリット**: 追加のホスティング先が不要で、公開版のURL
（`carpoolbridge-go.web.app/privacy`）だけで完結する。既存のCI/CDデプロイパイプライン
（`docs/12`）をそのまま流用できる。

**デメリット**: `src/router/index.tsx`のルート定義は自チーム版・公開版で共通のため、
このページは自チーム版ビルドにも含まれる（実害はないが、公開版専用の内容が
自チーム版にも存在する状態になる）。専用の`@app-shell`エイリアス側で出し分ける方法も
あるが、1画面のためだけに分岐を増やすのは過剰と判断し採用しない（YAGNI）。

# 5. `assetlinks.json`配信経路の準備

## 5.1 現状の技術的障害

`https://carpoolbridge-go.web.app/.well-known/assetlinks.json`にファイルを設置する
必要があるが、`firebase.json`の`hosting.ignore`に`"**/.*"`
（ドットで始まるファイル・ディレクトリを除外）が設定されているため、
`.well-known/assetlinks.json`は**このままではFirebase Hostingにデプロイされない**。

## 5.2 対応方針

`hosting.ignore`から`.well-known`配下だけを除外対象外にする。Firebase Hostingの
`ignore`は`.gitignore`と同様のglob構文で、否定パターン（`!`始まり）が使える。

```json
"ignore": [
  "firebase.json",
  "**/.*",
  "!.well-known/**",
  "**/node_modules/**"
]
```

否定パターンは対象パターンより後に書く必要があるため、`"**/.*"`の直後に追加する。

## 5.3 `assetlinks.json`本体は今回配置しない

`assetlinks.json`の中身（`package_name`・`sha256_cert_fingerprints`）は、TWAアプリの
パッケージ名と署名鍵のSHA-256フィンガープリントに依存する。これらは4.2節で対象外と
した「TWAラッパー生成・署名鍵発行」が終わるまで確定しない。

そのため本ドキュメントでは配信経路（`ignore`設定）の疎通確保のみを対象とし、
`assetlinks.json`ファイル自体の追加は、TWAラッパー生成後のタスクとする。
内容不明のまま仮の値を置くと、後で消し忘れて誤った検証情報が公開され続ける
リスクがあるため行わない。

# 6. プライバシーポリシーページ設計

## 6.1 ルーティング

`/privacy`に静的ページを追加する。`src/router/index.tsx`に他画面と同様
`React.lazy`でルート追加する（既存の画面分割方針を踏襲）。

認証・データ取得を伴わない静的コンテンツのため、`Header`の戻り先（`backTo`）は
`/`（ホーム）に固定する。

## 6.2 掲載内容

公開版はサーバーへ個人情報を送信しない設計（`docs/08`#2「公開版は個人情報を
サーバーへ送らない」）のため、内容は以下のように極めてシンプルになる。

- 取得する情報: なし（本アプリはお使いの端末のブラウザ内（IndexedDB）にのみ
  データを保存し、サーバーへ送信しない）
- Cookie・アクセス解析等のトラッキング: 不使用
- 第三者への情報提供: なし
- お問い合わせ先: 本アプリのGitHubリポジトリ（`tetteleee/carpoolbridge`、公開）の
  Issueページ

**人間への確認事項**: お問い合わせ先はGitHub Issueを暫定案としたが、専用の
連絡用メールアドレス等に差し替えたい場合は指示してほしい（テキストのみの
変更で対応可能）。

# 8. 「学童野球チーム向け」という性質上の留意点（人間の最終判断が必要）

本アプリの実際の利用者は保護者（配車担当者）であり、子ども自身が使うアプリでは
ない。Google Playの「対象年齢層」申告・「ファミリー向けポリシー」の要否は、
ストア申請フォームの実際の質問文を見ながら人間が最終判断する。本ドキュメントでは
判断材料として実態（利用者は保護者）のみを記録し、申告内容の確定は次フェーズの
ストア申請作業時に行う。
